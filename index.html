From coursework to quant dev

I study Technical Computer Science at the University of Twente and I'm working toward a career as a quantitative developer, where low-latency systems engineering meets financial models. I'm currently building C++ trading infrastructure for a cryptocurrency market-making system: real-time order book processing, a PostgreSQL/TimescaleDB time-series database, and benchmarks for critical-path latency and throughput.

Alongside my studies I'm an Investment Analyst, Financial Software Developer and External Affairs Board Member at investment society SBV Duitenberg, and a member of Rabobank's Members' Council. This site tracks what I build along the way: coursework, personal experiments, and the tools I pick up doing it.

What I've built

Hyperliquid: C++ Market Making Infra

active

Latency-sensitive C++ trading infrastructure for a crypto market-making system: order book management, market data handling, and quoting/execution logic driven by real-time websocket data. Includes benchmarks for critical-path latency and a PostgreSQL/TimescaleDB time-series database (with separate production and test environments) hosted on a Debian server, accessed via SSH.

C++ Market Making WebSockets TimescaleDB

C++ Limit Order Book & Simulator

active

A C++ limit order book implementing order matching, bid/ask management, and trade execution logic, built to model market microstructure and order book mechanics in a controlled environment. Matching runs on price-time priority.

C++ Order Matching Data Structures

Quarto: Java TCP Game Server

completed

Full Java TCP networking stack (server and client) for the board game Quarto: a custom application protocol, per-session state machine, thread-safe matchmaking, defensive input parsing, and disconnect handling. The server acts as single source of truth, re-validating every move server-side.

Java TCP Sockets Concurrency
